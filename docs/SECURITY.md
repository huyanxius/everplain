# Everplain 安全与隐私边界

这份说明描述代码与运维边界，不构成安全认证或合规承诺。

## 账号与数据

私有知识库、研究、会话、文稿和引用必须检查资源所有权。账号导出可能包含资料原文和对话，应按私人数据保存；注销删除不替代部署者对备份的保留与清理政策。初始化管理员凭据需独立、足够强，仅交给实际维护者。

用户上传的原始资料、正文、研究和账号信息保存在主 SQLite 数据库；数据库与备份均包含敏感内容。文件权限限制只是访问控制，不是加密。部署者需要决定磁盘与备份加密、异地保存、保留期限和读取权限。

研究功能会把完成请求所需的资料、对话或查询发送给配置的模型、向量、重排和网络检索服务；邮件和语音服务在启用时分别接收邮箱或音频。部署者应提供与实际供应商及数据保留策略一致的隐私说明，不能宣称资料始终不离开服务器。

## 密钥与运行隔离

只使用 `EVERPLAIN_` 配置。密钥只放未跟踪的 `backend/.env` 或部署环境；不放入浏览器变量、镜像、日志、Issue、PR、数据库备份说明或公开制品。不要打印解析后的 Compose 环境或完整 Settings。

Compose 仅暴露宿主机回环端口 5196 和 8297，独立使用 `everplain-data`、`everplain-backups`。不要与其他产品共享卷、cookie 名称、数据库或反向代理域名。API 使用非 root 用户、单 worker 和受保护的会话 cookie；生产入口必须提供 HTTPS。

## 上线前

运行配置预检必须通过。预检只校验配置形状和必需项，不证明密钥有效、模型可用、DNS/TLS 正确或邮件能够到达。容器健康检查也不是产品全链路验收。

在目标环境完成 HTTPS、真实服务访问、管理员和普通账号隔离、注册邮件投递、备份恢复及故障监控。当前 Nginx 速率限制是基础防护，多实例、应用网关与大规模流量策略需要单独设计。不要运行 `docker compose down -v` 作为常规升级动作。

## 问题报告

通过维护者的私下渠道提供受影响版本、最小复现和影响范围；不要在公开 Issue 粘贴资料正文、cookie、Authorization header 或漏洞可利用的秘密。尚未建立私下渠道时，先与仓库维护者确认接收方式。
