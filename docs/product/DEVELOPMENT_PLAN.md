# Everplain 开发计划

更新：2026-10-02。本计划取代 2026-09-16 开发报告里的阶段排序（那份写于定位调整之前，共享库、公共主题库排在第一位，并要恢复访谈编码入口）。报告中关于代码基线、复用地图和工程边界的记录仍然有效。

## 产品是什么

Everplain 是给文科学生、产品经理、老师这类非技术知识工作者用的个人完整知识库，加上一个只属于用户自己的 Agent。用户把看过的、收藏的、写过的东西放进来；想不起来时它帮你找，想不清楚时陪你讨论，需要动手时和你一起完成。

已经定下的取舍：

- 研究工具是核心，保留。文字工作者一定有研究需求。
- 访谈转写、质性编码属于社会学特色功能，和平台不兼容，删除。
- 共享库、公共主题库推到最后做。
- 主界面是卡片网格加搜索，图谱是次一级的视图。
- Agent 仍然按会话隔离，不做不分会话的单一长线程。
- Agent 的外观复用官网已经冻结的角色系统（`frontend/src/modules/agent-avatar`）：七个几何角色，共用眨眼、待机、思考、工作、打招呼五种动作，颜色可以单独换。

## 开发流程

每个子任务都按这个顺序走：

1. **调研**：先看竞品和成熟的开源方案，确认是最好的实现方式。许可证是 MIT、Apache、Unlicense 的可以移植；AGPL 的只借鉴设计，不抄代码。
2. **看群学已有代码**：能复用的就复用。以群学远端主线为准，本地工作树只当线索。
3. **设计架构，对照设计 token**：沿用现有的颜色、字号、间距和组件，确保风格不跑偏。
4. **实现**。
5. **验收要适度**：只做和影响面相称的检查，不写过度防御的代码。
6. **全部完成后**：推到 GitHub，提 PR、合并，然后部署。

## 第一期：Agent 引导流程 + 个人知识图谱

### 1. Agent 档案（后端）

新增 `modules/agent_profile`，存名字、角色 ID、颜色、说话风格和引导进度，问卷原文另存一份。问卷里提炼出的"做什么、哪个行业、想让它帮什么"拆成几条用户级记忆，写进现有的 `MemoryService`，来源标为"引导问卷"，这样在记忆面板里就能查看、修改、删除。接口契约用 `make contract` 生成。

验收：档案和问卷保存后刷新仍在；问卷生成的记忆出现在记忆面板里，删除后不再被 Agent 使用。

### 2. 导入底座和两个首批来源

新增导入批次：每一条记录来源、状态和来源键（网址或文件路径的哈希）。重复导入按来源键去重，失败的条目可以单独重试，部分失败不影响已经成功的条目。首批只接两种来源：

- **Chrome 书签**：用户上传浏览器导出的书签 HTML，后端用标准库解析；每个链接用现有的 trafilatura 抓正文后入库。
- **Obsidian / Markdown 文件夹**：前端选择整个文件夹上传，走现有的 Markdown 解析，`[[双链]]` 转成知识之间的关系。

验收：用真实的书签文件和一个真实的 Obsidian 库各导入一次；第二次导入不产生重复；失效链接显示失败原因，并且可以重试。

### 3. 引导流程（前端）

新路由 `/welcome/setup`，首次登录时跳转过来。每一步都可以跳过，以后在设置里可以重新进行。一共四步：

1. 导入已有的收藏。
2. 取名，从七个角色里挑一个，可以换颜色。
3. 填问卷，以选项为主，补充说明选填。
4. 等待生成：角色处于工作状态，进度取自导入批次的状态。

验收：真实浏览器里从注册走完四步；中途刷新能回到原来那一步；跳过任意一步都能正常进入下一步。

### 4. 个人图谱的数据

图谱从里到外四层：我、主题、资料、知识点。主题有两个来源：问卷里用户自己写的兴趣，以及对导入资料的归类。归类做法：用现有的嵌入向量，按余弦相似度做贪心聚类（不引入新依赖），再由模型给每一簇起名。首次导入只同步处理前 300 条，其余的放到后台继续，以控制模型成本。接口返回的结构与现有图谱组件的 `KnowledgeGraphProjection` 一致。

验收：混合导入之后，主题名称和归属大体合理；新的导入会增量更新图谱，不会整张重建。

### 5. 图谱视图

复用现有的 `ObsidianKnowledgeGraph`（cytoscape），改用同心圆布局：用户的角色在中心，主题在第一圈，资料在外圈。点开节点可以回到原文。引导完成后先进入这里，再进入对话。

验收：在真实数据下可以缩放、拖动、搜索，点击节点能打开原文；移动端可用。

### 6. Agent 人格注入

在 `pydantic_runner` 的系统提示里加入名字和说话风格。首次进入对话时，Agent 以用户挑选的角色，根据问卷内容打招呼。

验收：对话里它能说出自己的名字，引用导入的资料时带出处。

### 7. 删除访谈转写和质性编码

先删除前端入口和路由，后端模块单独开一个 PR 删除，避免误伤共用代码。

验收：界面上找不到入口；其余研究工具的流程不受影响。

### 第一期整体验收

用真实账号走一遍：导入书签和一个 Obsidian 库，取名、选角色、填问卷，看到图谱；在对话里，它能叫出自己的名字，并能引用导入的资料。最后在浏览器里交给用户验收，不截图。

## 第二期：其他导入来源

- **B 站收藏夹**：先做公开收藏夹，填 UID 即可读取。私密收藏夹需要用户提供登录 cookie，做不做由用户决定。视频用 yt-dlp：有字幕先取字幕，没有字幕再用现有的 DashScope 转写；只保存转写稿和元数据，不保存视频文件。
- **Apple 备忘录**：网页端读不到本机的备忘录库，先支持用户导出 Markdown 后上传。真正的一键导入需要做一个 macOS 小助手，单独评估。
- **印象笔记 ENEX、Notion 导出包、flomo、Google Keep**：移植 obsidian-importer（MIT 许可）的解析器，统一转成导入批次。
- **浏览器扩展**：Chrome MV3。用 `chrome.bookmarks` 一键导入全部书签，并支持当前页面一键收藏，正文用 Defuddle 提取。
- **图片整理**：先让模型网关支持图片输入，再用视觉模型做文字识别和内容描述。

## 推后

共享库、公共主题库、外部 Agent 接入、订阅支付和模型目录。

## 风险

- 首次聚类是第一期主要的模型开销，已经用"前 300 条"的上限压住。
- B 站私密收藏需要保存用户的 cookie，涉及凭据的保管。
- yt-dlp 抓取视频要留意平台条款。
- Apple 备忘录受系统限制，第二期先只能做导出文件上传。
