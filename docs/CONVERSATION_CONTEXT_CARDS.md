# 对话建议卡片：展示内容与背景分离

## 对外契约

- 对话建议只公开 `card_id`、`version`、`title`、`description` 和已验证的 `sources`。不公开模型生成的 `prompt`，旧缓存同样使用公共投影。若模型把技术定位符写进展示字段，拒绝该卡片，不通过文本抹除把它伪装成合法建议。
- 点击建议选择一张可移除的卡片，不发送消息。输入框用于可选的自然语言补充；只有用户明确发送才创建执行请求。
- `AgentTurnRequest.message` 只包含可见卡片文字和用户补充。可选的 `context_suggestion` 仅携带卡片标识与版本，不接受客户端执行指令或来源快照。
- 消息历史、运行恢复和查询使用独立的 `context_card`（仅标题和描述）显示卡片。没有服务器卡片标记的普通文本不会被猜测成卡片请求。

## 服务端边界

卡片标识在当前所有者范围内查回，不是持有即授权的令牌，不使用新密钥。
发送前重新验证缓存版本、来源存在性、所有者、记忆设置与来源内容。模型生成的引用只能在既有可读来源集合中匹配，不能授予其他数据或工具权限。

执行时，用户消息与被验证的背景数据分离。背景是历史事实候选，不是执行指令，不表示用户同意历史建议，也不能提供额外的写入、外联或付款授权。模型生成的旧卡片 `prompt` 不参与执行。

服务器保留私有卡片来源快照，使已发起请求的显式重试不因建议缓存刷新而失效；重试仍须检查原文及权限。来源被删除、修改或权限撤销时，以可读错误结束，不退回明文内部提示词。已完成请求的重放只读取结果，不再执行。

## 可见数据与恢复

- `message` 只来自可见文字；选卡创建的新会话以已验证的卡片标题命名，不通过模型把隐藏背景改写成标题。
- 历史卡片展示快照只含标题和描述；用户补充保持原样。
- 草稿、刷新、返回或文本相等都不构成隐藏卡片授权。新选择不会存入可自动执行的持久草稿。
- 普通发送不会根据内容相等自动复用失败的卡片执行。只有显式重试沿用原请求。
- 账户导出保留用户原文、可见请求和卡片，但不导出内部执行字段或原始卡片缓存中的提示词。

## 兼容范围

此修复不需要批量修改旧消息。旧版本曾把内部提示词直接存成普通用户文本，并且没有保存可靠的卡片来源标记；本修复不猜测或重写这些历史原文。不根据 UUID、关键字或文本形状删除内容。若要修复此类既有记录，应在另一个有证据的窄范围修复中处理。

验证使用合成账户、合成来源与本地替身，不代表真实模型、生产或真实浏览器全链路验收。

前后端需要同版发布。新前端遇到没有标识/版本的旧卡片时提示刷新，不回退到发送 `prompt`；部署后应刷新旧版前端页面。
