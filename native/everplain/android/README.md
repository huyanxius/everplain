# Everplain Android native client

Kotlin + Jetpack Compose, Android 8.0/API 26 or later. No WebView, browser
wrapper, production mocks, embedded credentials or provider SDKs.

## Scope

- Home with the real Agent greeting and independent conversation history
- New chat with server-supplied model/reasoning choices and an explicit web-search
  toggle, POST SSE, Stop confirmation, canonical completion and same-key recovery
- Native CommonMark/GFM answer rendering, selectable text and copy; HTTP(S) links
  open only on user action. No WebView, HTML runtime or automatic remote images.
- Account display-name CAS editing, usage and active sessions; remote logout and clearly
  distinguished local-only logout
- Agent name, seven original avatars, color, speaking-style enum and soul text;
  optimistic-version save with retained drafts and explicit 409 conflict review

The requested scope expanded on 2026-10-04 to the live Web core, including library,
files, personal graph, deep research and project workspaces, excluding the separate
More navigation group. These additional modules are in progress, not yet release
complete. The current compiled surface must not be advertised as the full migration.

The email-first login, password visibility/back flow, registration code/password
flow, canonical NavIcon/Phosphor geometry and default verified origin are native.
Registration transport tests use only local synthetic fixtures; no real account or
verification email was created. Motion ports are being revalidated on a real software
Android emulator; compilation alone is not visual acceptance.

## Build

Pinned toolchain: JDK 21 (Java/Kotlin output 17), Gradle 8.11.1, Android Gradle
Plugin 8.9.2, Kotlin 2.1.20, Android SDK 35 / Build Tools 35.0.0. Install SDK
components through the official Android tools, after accepting the SDK license.
Set `ANDROID_HOME` or a local, ignored `local.properties` (`sdk.dir=...`).

From this folder:

```sh
./gradlew :core:test :app:assembleDebug :app:lintDebug
./gradlew :app:connectedDebugAndroidTest
```

The checked-in wrapper is generated by the official Gradle distribution and
pins its SHA-256 checksum. Regenerate it only when updating Gradle. No release
signing key is supplied. A debug APK, if built, is not a signed store release.

The app consumes `../contracts/generated/EverplainContracts.kt` and
`../tokens/generated/EverplainTokens.kt` via source sets. `syncAvatars` packages
the canonical `../tokens/assets/avatars.json`; `syncMotionAssets` includes the shared
120-radius contours and source animation parameters. It does not ship Web source.
Regenerate shared files with the root shared generators before building after a
contract/token update. Do not hand-edit generated DTOs or tokens.

## Connect

At first launch, enter the HTTPS origin of the existing Everplain server (domain
and optional port only, without `/api`, query, credentials or fragment), then
log in with an existing account. No deployment hostname is guessed. Redirects
are rejected; the app does not disable TLS validation or forge browser Origin.
Registration uses the live email-code/password flow. No production registration was performed during fixture verification.

One origin-scoped OkHttp cookie client serves all API and SSE requests. Password
input is held only for the login call and cleared immediately on submit; it is
not a saved Compose field. Android Keystore AES-GCM encrypts persisted cookies
and the minimal pending-turn recovery envelope. Auto backup and device-transfer
extraction are disabled. The app requests the normal INTERNET permission. AndroidX also adds its own signature-only internal receiver permission; there are no dangerous runtime permission requests.

## Backend capability

The candidate also consumes `GET /api/agent/runs/by-idempotency-key` from the
root `backend-lookup` patch. That patch must be deployed to provide authoritative
pre-start run identity recovery; building this APK does not deploy it. Older
servers remain usable, but a missing lookup route/run retains outcome-unknown
state and cannot prove whether a cancelled pre-start request executed.

## Reliability

- SSE decoder processes UTF-8 byte chunks, CR/LF/CRLF, BOM, comments and multiline
  fields incrementally with a bounded event size. Unknown events are ignored by
  the application layer. EOF without a terminal event is interruption.
- Stop sends a stable idempotency key and waits for the server to confirm a
  non-running status. Disconnecting a stream alone is never called a confirmed
  server stop. Retry restores the original request/key, not a new charged turn.
- Relaunch restores the encrypted pending identity and performs the owner-scoped
  read-only run lookup using the ORIGINAL Idempotency-Key header. A known
  conversation remains a fallback for old servers. 404 preserves an unknown
  outcome; it never means "not executed." The separate 核对状态 action does not
  POST a turn. Resume requires an explicit user tap and can continue billable work.
- Pre-start Stop cancels local transport, retains the exact original intent and
  looks up the run. A discovered running run goes through the existing confirmed
  Stop flow. If no run is found, the UI explicitly keeps server stop unconfirmed.
- Sessions are revalidated on foreground. A 401 clears authenticated state and
  private caches. Generation/account guards reject stale response callbacks.
- Agent save uses `expected_version`; a 409 keeps the local draft, retrieves the
  current profile and asks the user to compare/reapply. Transport retry preserves
  the save intent key. Speaking style and length constraints match the schema.
- Compose uses native text selection/copy, password controls, system typography,
  persisted light/dark/system mode, safe drawing/IME insets, a controlled streaming composer
  that rejects in-flight edits without disabling its native input session, and Back handling that does not silently lose an active run.

## Validation boundaries

The synthetic shared-fixture and MockWebServer tests exercise codecs and protocol
behavior. They are test-only and are never runtime fallback data. A passing unit
or build task does not verify the real backend, real model or native interaction.

See `VERIFICATION.md` for exact executed results and remaining release gates.
Live login/model calls, physical-device/Pinyin coverage, release signing and store
distribution remain separate release gates. Emulator fixture checks do not
substitute for those. Markwon 4.6.2 is Apache-2.0; its license is bundled in assets.
